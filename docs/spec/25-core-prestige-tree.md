# 25 Core: 常連ツリー（常連P の使い道, D-100〜D-103）
参考: Cookie Clicker の天国チップと天国のアップグレード（調査 `docs/ref/cookie-clicker-heavenly.md`）。
閉店（転生）で貯まる常連P を「使って」永続の能力（ノード）を開ける。ノードは閉店でリセットしない。
数値・一覧は `resources/economy/default.json` の `tree` に置き、コードに直書きしない。以下は初期値。

## 目的
- 閉店を重ねて **数週間〜数か月単位で遊べる**ようにする。標準的な行動で全部そろうまで約12か月、多めで約8か月。
- 短期（〜2週）・中期（〜2か月）・長期（〜6か月）・超長期（6か月〜）のどの時期にも「次に買う面白い物」があり、買い物の目標が途切れない（最大の間隔は標準で約4週）。
- 常連P は行動（メダル）が決める（D-049）。ツリーは行動を続けた人の店を少しずつ楽に・にぎやかにし、倍率の伸びが鈍る後半を支える。
- 1日数分の遊び方に合わせ、操作は閉店の前後に1〜2タップ。iPhone 縦画面の1枚のシートで完結する。

## 常連ランクと常連P（D-100）
これまでの「常連P」（閉店で +gain、生産 ×(1 + 1.0×常連P)）は **常連ランク** と呼び直す。計算・保存・獲得式（D-049）は一切変えない。
新しく、使う通貨としての **常連P** を足す。閉店で次の量を得る（gain はランクの増分）:
```
gain = max(0, min(玉由来, 行動由来) − 既得ランク)            # 既存（D-049）のまま
常連P = gain ≥ 1 なら  points_per_rank × gain + runBonus + Σ口コミ   それ以外 0
runBonus = 今回の累計玉が run_bonus_at の何個以上か               # 初期 [1e11, 1e12, 1e13, 1e14, 1e15, 1e16] → 0〜6
points_per_rank = 10
```
- ランク（＝常連倍率）は使っても減らない。常連P は使うと減る。画面は「常連ランク n（生産 ×…）」と「常連P m」を分けて出す。
- **gain 0 の閉店では常連P も 0**。行動なしは今までどおり何も貯まらない（runBonus だけ取る抜け道が無い）。
- runBonus は「周回で遠くまで行くほど少し多い」。閉店を遅らせて gain をまとめても runBonus は1回分なので、毎週閉める人が損をしない（遅らせる得は累計玉の段が上がる時だけ）。
- 比較: 獲得式そのもの（`medals_per_point` 等）を変えると閉店日が動き、初閉店 5日目・閉店日の一致（P9-T5）が崩れる。ランクと通貨を分ければ不変条件を守ったまま通貨の量だけ設計できる。

### 獲得の目安
メダル/週は spec/30 の換算（歩数 2,000歩ごと +1・1日 10,000歩まで、運動 10分ごと +1・1日 60分まで、階段 10階ごと +1・1日 30階まで）。
ランク ≒ floor(累計獲得メダル / 28)（`pachisim econ` 84日 light seed1 standard で、78日目に玉由来 40 / 行動由来 15。閉店日 5/10/15/19/25/30/…/83 各 +1）。
runBonus は 1〜2週 1・〜8週 2・〜20週 3・以後 4 と仮定（sim の閉店時の今回累計玉 1e11〜1e14 から。T5 で実測に置き換える）。
| プロファイル | メダル/週 | ランク 12週 / 52週 | 1閉店の常連P（序盤 → 終盤） | 常連P/週（序盤 → 終盤） |
|---|---|---|---|---|
| 少なめ（5,000歩＋週1回ジム60分） | 20 | 8 / 37 | 11 → 18 | 8 → 13 |
| 標準（8,000歩＋週2回ジム60分。sim standard） | 40 | 17 / 74 | 11 → 18 | 16 → 26 |
| 多め（12,000歩＋週4回ジム90分。sim heavy） | 59 | 25 / 109 | 11 → 18 | 23 → 38 |
| 上限（毎日 歩数・運動・階段とも上限） | 98 | 42 / 182 | 11 → 18 | 39 → 63 |
| 行動なし | 0 | 0 / 0 | 0 | 0 |
- 1閉店あたりの量が runBonus と口コミで約1.6倍に伸びるので、線形のランクより後半がやや速い（コストの増え方 約×2〜3/段 の方が大きいので、後半ほど1つに数週間かかる）。

## 設計方針（Cookie Clicker から採るもの・採らないもの）
| Cookie Clicker | 採否 | 理由 |
|---|---|---|
| チップを使っても倍率は下がらない | **採る**（ランクと通貨を分けて実現） | 買い物の失敗が無い。行動の成果が減る罰にならない |
| 親ノードで子が開く・合流 | 採る＋**段（tier）**: 下の段の購入数で次の段が開く | 一本道にせず、各段で買う順番を選べる。段が「次の時期」の目印になる |
| 序盤の安いノード（Starter kit 等）・オフライン系・黄金クッキー系 | 採る（開店・放置・燃料・予告） | PocketHeso の放置＝営業時間と放置効率、黄金クッキー＝予告 |
| 永続スロット | 形を変えて採る | 選ぶ UI を作らず「◯◯の段を閉店で保持」の固定ノード |
| 利便性（一括購入・ラベル） | 採る（予告の自動受け取り・番頭さん＝役物の自動購入） | 1日数分の遊び方に効く |
| 装飾・小ネタ（Fortune 等） | 採る（見た目の解放 5 個） | 生産を増やさずに種類を増やせる |
| コスト 7 の冪・10倍刻み・総額 7.5e16・Unshackled | **採らない** | 常連P の獲得はほぼ線形。段ごと ×2〜3 で、終盤の大物でも 100〜120 P（数か月分の貯金）に収める |
| 季節・砂糖塊・ドラゴン・Golden switch・Lucky digit | 採らない（未決事項） | 別システムが増える |
| 購入は転生画面の中だけ | 採らない | いつでも買える。閉店のシートにも入口 |

## 効果の種類（effect.k）と計算
すべて四則・比較・表引きだけ（AGENTS.md の禁止演算を使わない）。集計は一覧の**添字順**に、持っているかの真偽配列で見る（Map/Set・キー順に依存しない）。
加算型は合計に上限を検証時にかける（下表）。値はすべて JSON。
| k | 値 | 計算 | 合計の上限（検証） |
|---|---|---|---|
| `prod_add` | add | `treeMult = 1 + Σprod_add + Σ(今の機種の prod_add_machine)` | Σ ≤ 1.0 |
| `prod_add_machine` | machine, add | 今の周回の機種 id が一致する時だけ treeMult に足す | 機種ごと Σ ≤ 0.3 |
| `regular_add` | add | 常連倍率 = `1 + (close.regular_mult + Σ) × ランク` | Σ ≤ 0.2 |
| `ach_per_add` | add | `achMult = 1 + (mult_per + Σ) × 達成数` | Σ ≤ 0.006 |
| `streak_max_add` | add（日） | streakMult の上限日数 = `streak_max_days + Σ` | Σ ≤ 10 |
| `price_sub` | sub | 役物の価格 = 既存の価格 × `(1 − Σ)` | Σ ≤ 0.10 |
| `keep` | targets（idle tank nail shorten hold auto tomeuchi） | 閉店のリセットでその強化の段を戻さない | — |
| `starter` | lv（8 要素） | 閉店のリセット後に役物 Lv = 各要素の最大（覚醒は 0）。`lv[i]>0` なら `lv[i−1]>0` | 各 ≤ 100 |
| `open_boost` | ms, mult | 閉店時 `openBoostMs = Σms`。tick ごとに燃料・前面背面を問わず実時間で減る。残りがある間 perSec × `(1 + Σ(mult−1))` | Σms ≤ 8h・倍率 ≤ 3 |
| `closed_add` | add | 燃料切れの状態係数 = `factors.closed + Σ` | 合計 ≤ 0.05 |
| `tank_add_h` / `boost_cap_add_h` | add | タンク上限 = `(tank_hours[段] + Σ) h`、ブースト上限 = `(boost_cap_hours + Σ) h` | 各 ≤ 24 |
| `boost_mult_add` | add | ブースト倍率 = `factors.boost_mult + Σ` | Σ ≤ 1 |
| `notice_interval_sub` | sub | 予告 n の間隔 = `floor((min + floor(unit×(max−min))) × (1 − Σ))` | Σ ≤ 0.3 |
| `fever_ms_add` / `fever_mult_add` | add | 確変フィーバーの時間・倍率に足す | 30秒・2 |
| `rush_cap_add_s` | add | 出玉ラッシュ `min(玉×0.15, perSec×(900+Σ))` | 600 |
| `notice_bonus_weight_add` | add | ボーナス抽選の重みに足す（他の重みは不変） | 10 |
| `notice_auto` | ms | 前面で出た予告を `出現 + ms` に自動で受け取る（それまでに手で押せばその時刻） | 1 個まで |
| `grant_hold_1_in` | value | 行動の特別保留（Grant.bonusHolds）の当たり 1/value（予告のボーナス保留は 1/10 のまま） | 5〜10・1 個まで |
| `awaken_medal_base` | value | 覚醒のメダル = `value × 2^n` | `awaken.medal_base` 未満・1 個まで |
| `prod_min_add` | add | Grant の即時の玉 = `refPerSec × prodMin × (1 + Σ) × 60` | Σ ≤ 0.5 |
| `points_add` | add | 閉店の常連P に足す（gain ≥ 1 の時だけ） | Σ ≤ 5 |
| `bantou` | — | 役物の自動購入を解放（下記） | 1 個まで |
| `unlock` | key | 見た目の解放（Core は所持だけ。描画・演出が key を見る） | — |

生産の式（spec/23・spec/24 に足す）:
```
perSec    = Σ役物 × (1 + r×ランク) × streakMult × achMult × treeMult × boost × 予告フィーバー × openBoost × 状態係数
refPerSec = max(Σ役物 × (1 + r×ランク) × streakMult × achMult × treeMult, prod_ref.min_per_sec)
r = close.regular_mult（1.0）+ Σregular_add
```
- treeMult は refPerSec にも掛ける（行動の即時報酬・玉の単価の単位も一緒に伸びる。spec/23 の「基準生産で量る」を保つ）。
- openBoost は refPerSec に**掛けない**（閉店直後に行動を受け取ると即時の玉が増える抜け道を作らない。ブースト・予告フィーバーと同じ扱い）。
- 効果は購入の次の economyTick から（spec/24 の achMult と同じ）。keep・starter・openBoost は次の閉店で効く。予告は次に決める間隔／次に発動するフィーバーから。

### 番頭さん（役物の自動購入）
- ON の間、economyTick の時刻が 60,000ms の倍数の時に、持ち玉の `tree.bantou.share`（初期 0.5）を上限に、「次の Lv が最も安い役物」を1 Lv ずつ買う（同額は添字の小さい方。1回の上限 `tree.bantou.max_per_run` 100 Lv）。
- 解放の条件（前の役物 Lv1）・マイルストーン・覚醒は手で買う時と同じ。覚醒・強化・レート解放は買わない。
- Action `{ k: 'bantou'; on: boolean }`（未所持なら rejected）。lookahead・留守中も同じ規則で動く（入力なしの仮定に含める）。性能: 24時間の advance で 1,440 回の判定、各回は8要素の比較だけ。

### 守る不変条件（バランスの柱）
1. **常連ランクの獲得と閉店条件を変えない**: メダル・累計獲得メダル・`close.medals_per_point`・`close.divisor`・閉店条件（今回の累計玉 ≥ 1e10）に触れる効果を作らない。
   → ツリーの有無で閉店日と各回の gain が変わらない。初閉店 5日目のまま。行動なしはランク 0・常連P 0 でツリーも空。
   （sim の閉店は「gain ≥ 1 ならすぐ閉める」なので、ツリーで今回の累計玉が早く 1e10 に届いても閉店日は変わらない）
2. **パチンコの期待値の上限を上げない**: 釘・変動短縮・保留+1 は段の保持だけ。予告・フィーバー・開店ダッシュは生産倍率で、EV（出玉だけ）に入らない。
   特別保留の 1/8 は無料の保留だけ（rate1、EV の計測外。1日最大3つ）。
3. **初閉店まで何も変わらない**: 1周目（打ち方 1〜3・玉の内訳 1〜7日目）は不変。
4. **生産の天井**: 加算は各系統の合計に上限があり、全取得で `treeMult ≤ 2.3`・常連係数 1.2・実績 1個 1.6%・連続 30日。乗算で積み上がる系統の数を固定する（新しい乗算の系統は足さない）。

## 倍率の重なり（暴走しないか）
標準・上の購入順・連続日数が毎日つながる・実績は sim の実測程度（12週 20個・26週 28個・52週 36個）として、燃料ありの生産倍率:
| 週 | ランク | ツリーなし `(1+R)×streak×ach` | ツリーあり（light の台） | 比 | 役物 Lv 換算（値下げ込み） |
|---|---|---|---|---|---|
| 4 | 5 | 14 | 15 | ×1.10 | +0.7 Lv |
| 12 | 17 | 43 | 52 | ×1.20 | +1.3 Lv |
| 26 | 37 | 97 | 177 | ×1.82 | +4.7 Lv |
| 39 | 55 | 148 | 445 | ×3.01 | +8.6 Lv |
| 52 | 74 | 204 | 814 | ×3.99 | +10.7 Lv |
- 天井は全取得で **×約4.0**（treeMult 2.3 × 常連係数 約1.2 × 実績 約1.18 × 連続 1.25）＋前面だけのブースト・予告・閉店直後の開店ダッシュ。
- 役物の価格は 1.15^Lv なので ×4（値下げ込み ×4.4）は各役物 +10.7 Lv ぶん。値段が絶対値の項目（役物・強化・閉店条件・実績のしきい値）が早く届くだけで、
  行動の即時報酬・玉の単価・大当たりは refPerSec 基準なので相対の重みは変わらない（D-080・D-090）。
- 生産系の大物（繁盛店・名店・常連の格・伝説の常連）は 25週以降に置いた。ランク+1 の伸びが ×1.03（ランク36）→ ×1.013（ランク74）と鈍る時期を支える（spec/23 の「12週の伸びが鈍りすぎないか」への回答の一部）。
- 効率は逓減する: 常連の看板 +10%/3P（3.3%/P）→ 伝説の常連 +30%/100P（0.3%/P）。
- 上限プロファイル1年（ランク 182）でも全体の倍率は約2,900（ツリーなし 約530）で、double の範囲・Amount（D-069）に影響しない。

## 購入のルール
- 購入: `常連P ≥ cost`・段が開いている・`req` を全部所持・未所持。**いつでも**買える（大当たり中・閉店直後も可）。
- 返金・振り直しは**無し**（全ノードはいずれ買えるので、選ぶのは順番だけ）。未決事項 2。
- 閉店で保持。セーブのリセット（設定）でだけ消える。
- 一覧から消した id は効果を数えず、その cost を常連P に返す（復元時に計算。spec/24 の「消えた id は数えない」と同じ流儀）。コストを後で変えても過去の購入は買った時のコストのまま。

## 保存（IdleEconomy v7）・移行
- 追加: `points: number`（今持っている常連P）・`pointsEarned: number`（累計。表示と検証用）・`tree: { id: string; cost: number; at: number }[]`（購入順）・`openBoostMs: number`・`bantouOn: boolean`。
  既存の `regular` は常連ランクとしてそのまま。効果は復元時に一覧の添字順で集計し直す（キャッシュは保存しない）。
- 検証: `points ≥ 0`・`pointsEarned = points + Σcost（一覧にある id）+ 消えた id の cost`・cost は1以上の整数。未知の id は残して数えない。
- v6 以前: `points = pointsEarned = points_per_rank × regular`（過去の runBonus は分からないので0）・tree 空・openBoostMs 0・bantouOn false。
  既存セーブはランクぶんの常連P を持って始まる（ランク5の人は 50 P で段1を全部と段2の一部が買える）。
- web の `SNAPSHOT_VERSION` 5 → 6（3・4・5 も読む）。EngineSnapshot は変えない。golden は経済の保存項目が増えて変わり得る（新ハッシュを DECISIONS に）。

```json
"tree": {
  "points_per_rank": 10,

    ...
  ]

```
読み込み時の検証（エラー）: id 重複／req が未知・自分以降の添字・自分より上の段／tier が 1〜5 の外・`tier_unlock` の長さ違い・非減少でない／cost が 1 未満・非整数／

`tree` が無い JSON は空のツリーで、常連P は貯まるが使えない（試算の比較用 `--economy` もこれで作れる）。

## Engine・Action・イベント・Projection（spec/22 に追加）
```ts
type Action = ...
  | { t: SimTime; k: 'treeBuy'; node: string }   // rejected: 'unknown-node' | 'owned' | 'tier-locked' | 'locked'（前提不足）| 'insufficient-points'
  | { t: SimTime; k: 'bantou'; on: boolean }     // rejected: 'not-owned'

```
- 購入の成功はイベントを出さない（`buy`・`awaken` と同じ。状態と Projection に出る）。自動の受け取りは手のタップと同じ経路（`noticeTap` 相当を Engine 内で処理、イベントは既存のまま）。
- 番頭さんの購入はイベントにしない（経済の毎秒の増減と同じ扱い）。Projection の役物 Lv で見える。
- Engine は予告の設定を `getNoticeConfig()`（ツリー込み）から、機種 id を経済に渡して `prod_add_machine` を決める。
```ts
tree: {
  rank: number; regularRate: number      // 常連ランクと係数 r
  points: number; pointsEarned: number
  mult: number                           // treeMult（今の機種込み）
  openBoostMs: number; bantou: { owned: boolean; on: boolean }
  tierOpen: boolean[]                    // 段1〜5
  nodes: { id: string; tier: number; cost: number; req: string[]; state: 'owned' | 'buyable' | 'short' | 'locked' }[]  // JSON の順
  unlocks: string[]                      // 所持している unlock の key
  nextClosePoints: number                // 今閉店したら得る常連P（ShopView の閉店見込みにも）
}
```
