# 31 iOS Shortcut: ヘルスケア同期
有料 Developer Program 不要（読むのは Apple 純正「ショートカット」アプリ, D-012）。
**ヘルスケアはロック後10分で暗号化され読めない** → 自動実行ではなく、PWA から利用者が起動するのが主経路。

## 利用者の流れ
1. 初回: PWA の設定で「ショートカット連携」→ ペアリング鍵（16文字）を表示 → iCloud リンクからショートカットを追加し、
   追加時の質問に鍵を貼る → ヘルスケアの読み取りを許可（歩数・距離・上った階数）。
2. 毎回: PWA の「運動を受け取る」→ `shortcuts://run-shortcut?name=PocketHeso%20Sync` が開く → ショートカットが
   コードをクリップボードへコピーし「PocketHeso に戻って貼り付けてください」と通知 → 利用者が PWA に戻る →
   「貼り付けて受け取る」（`navigator.clipboard.readText()`、失敗時はテキスト欄に手で貼る）→ 確認画面 → 確定。
3. オートメーション（時刻で自動実行）は使わない（D-023）。受け取り忘れは、翌日以降の手動実行で3日分まとめて受け取れる。

## ショートカットの中身（`resources/shortcut/` に手順書と iCloud リンクを置く）
```
1 テキスト: <ペアリング鍵>                         （追加時の質問で入力）
2 日付ループ n = 0,1,2:
    ヘルスケアサンプルを検索 種類=歩数, 開始日=その日の0:00〜24:00 → 統計を計算(合計) → steps
    ヘルスケアサンプルを検索 種類=ウォーキング+ランニングの距離 同上 → distM
    ヘルスケアサンプルを検索 種類=上った階数 同上 → fl                 （D-083）
3 辞書 → JSON: {"v":1,"gen":"<ISO8601 now>","tz":"+09:00",
                "days":[{"d":"2026-09-24","steps":8234,"distM":6120,"fl":12}, …]}
4 Base64 エンコード(JSON) → b64
5 ハッシュを生成 SHA256(鍵 + b64) → 先頭16文字 → sig
6 クリップボードにコピー: "PH1." + b64 + "." + sig
7 通知を表示: "PocketHeso に戻って貼り付けてください"
```
- ワークアウトは取得しない（D-022）。iOS 26 の「ヘルスケアサンプルを検索」に種類が無く、ワークアウト系アクションは開始/記録/終了のみ。
  トレーニングの報酬はチェックイン（spec/32）で扱う。
- ハッシュは改ざん防止ではなく「別端末・別人の鍵」「壊れたコピー」を弾くためのもの（鍵は利用者から見える）。
- ショートカットの日付・言語設定差（数値の区切りなど）は PWA 側で吸収する。

## PWA 側の検証（`claims.parseShortcutCode`）
- 形式 `PH1.<b64>.<sig16>`、`v == 1`、sig 一致、`gen` が now の ±30分以内（古いコードの貼り間違い防止）。
- 範囲: steps 0〜100,000/日、distM 0〜100,000/日、fl 0〜1,000/日、日数 ≤ 3。外れた項目は捨てて警告。
- `fl` は任意項目（D-083）。無いコード（階数を足す前のショートカット）は 0 扱いで、v は 1 のまま。
- 結果は spec/30 の差分方式で Grant 化。確認画面に「今回増える燃料・メダル」を出してから確定。

## 実機で確認が必要（P0-T3）
- ホーム画面 PWA から `shortcuts://` を開けるか、戻った時に `visibilitychange` が来るか、`clipboard.readText()` の許可 UI。
- 「ヘルスケアサンプルを検索」の日付範囲指定と、統計「合計」が歩数の重複（iPhone+Watch）を除いた値になるか。
- 種類に「上った階数」があり、日の合計がヘルスケアアプリの表示と一致するか（P7-T11。iPhone 単体は気圧計で記録する想定）。
