# Graphics Bake-off（描画担当の比較手順）
Opus 5.5（Claude Code）と Muse Spark 1.3（OpenCode）の描画・見た目の出来を、同じ課題で比べて P5/P6 の描画タスクの Owner を決める（D-042）。
実施は P5-T0。P6-T2 の前に液晶演出で再比較したくなったら、課題を差し替えて同じ手順で行う。

## 条件をそろえる
- 起点は同じ `dev` のコミット。ブランチは `bakeoff/opus` と `bakeoff/muse`（`dev` にも `main` にもマージしない）。
- 各エージェントは新しいセッションで、下の「共通プロンプト」をそのまま渡す。追加の説明はしない。
- 修正指示は最大2回。文面は「修正指示テンプレ」だけを使い、`<>` 内に実機で見た問題を書く（両者に同じ観点で）。
- 所要時間と消費トークン（または残量の減り）を控えておく。
- 両ブランチを push し、Vercel のプレビュー URL を iPhone 16e のホーム画面アプリで開く。
  見比べる時は、どちらがどのモデルかを伏せて A/B として見る（URL を別の人に並べ替えてもらうか、メモで伏せる）。

## 共通プロンプト（そのままコピーして渡す）
```
PocketHeso の描画比較用スパイクを作ってください。AGENTS.md の読み込みルールは守りつつ、今回は次のファイルだけ読んでよい:
docs/spec/50-app-rendering.md, docs/spec/20-core-physics.md（盤面 JSON 節）, apps/web/src/spikes/ 配下（参考にしてよい）,
packages/core/src/index.ts（公開 API）, resources/boards/default.json。

作るもの: `?spike=bakeoff` で開くページ（SPIKE_NAMES に 'bakeoff' を足し、spike-root から lazy import。本体バンドルに混ぜない）。
- spec/50 の構成・奥行き・質感・描画方針に従って、default.json の盤面を Three.js で描く
  （盤面板は Canvas 2D で焼いた1枚のテクスチャ、釘は InstancedMesh 1つ、枠・ガラス・液晶の面も置く）。
- 役物を盤面 JSON の位置に置いて回す。
- 玉を常時打ち続けている見た目にする: @ph/core の BallSimulator で軌跡を事前計算し、同時最大20玉を毎フレーム補間で再生。
- 枠ランプを emissive で光らせる。画面タップで「当たり演出」: 全画面の虹フラッシュ（加算シェーダのクアッド）＋ブルームを3秒だけ ON。
- 左上に fps・draw call 数を小さく表示（frame-stats.ts を使ってよい）。
- パチンコ実機らしく「見ていて気持ちいい」見た目を目指す。色・光・動きの工夫は自由。外部素材は使わない。

制約: packages/core は変更しない。three は名前付き import のみ。`scripts/build.sh` が通ること。
コミットは1つ、メッセージは `[BAKEOFF] <モデル名> 描画スパイク`。現在のブランチ（bakeoff/*）に push まで行う。
最後に、工夫した点・spec から外れた点・既知の問題を5行以内で報告してください。
```

## 修正指示テンプレ
```
実機（iPhone 16e ホーム画面アプリ）で確認した結果、次を直してください: <問題を箇条書き>
制約は最初の依頼と同じ。直したら同じブランチに1コミット追加して push し、変更点を3行で報告してください。
```

## 評価表（STATUS Notes と DECISIONS に要約を残す）
| 観点 | 測り方 | A | B |
|---|---|---|---|
| 見た目（盤面・玉・光） | 人間が 1〜5。伏せたまま付ける | | |
| 当たり演出の気持ちよさ | 人間が 1〜5 | | |
| fps（通常時 / 演出中） | 画面の表示。目標 60 / 40 以上（spec/50） | | |
| draw call（通常時） | 画面の表示。目標 150 以下 | | |
| spec/50 準拠 | 奥行き順・質感値・InstancedMesh・DOM の HUD・名前付き import | | |
| 修正への反応 | 指示どおり直ったか・何回で収束したか | | |
| コードの読みやすさ | もう一方のエージェントで `git diff dev..bakeoff/<x>` をレビュー | | |
| 所要時間・トークン | 控えた値 | | |

## 結果の反映
- 見た目・演出の点を最優先し、fps と spec 準拠は足切り（目標を大きく外したら減点）として扱う。
- 勝った側を P5-T2・P5-T3・P6-T2 の Owner にする（僅差なら今の推奨のまま）。`docs/ref/tooling.md` の分担表も合わせて直す。
- 勝った側のブランチのコードは P5-T2 で流用してよい。比較用ブランチは結果を記録した後に削除してよい。
