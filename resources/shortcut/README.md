# PocketHeso Sync（iOS ショートカット）

iPhone のヘルスケアから**今日・昨日・一昨日の歩数と歩行距離**を読み、PocketHeso に渡すためのショートカット。
ショートカット名は **`PocketHeso Sync`**（PocketHeso がこの名前で起動するので変えない）。仕様: docs/spec/31-shortcut-health.md。

**iCloud 共有リンク**: （未作成。作者が「2. 作り方」の 2-5 で作成して記入する）

## 1. 使い方（利用者向け）

### 1-1 はじめに1回だけ
1. PocketHeso（ホーム画面のアプリ）の **設定 →「ショートカット連携」** を開き、表示される **16文字のペアリング鍵** をコピーする。
2. 上の **iCloud 共有リンク** を iPhone の Safari で開き、「ショートカットを追加」をタップ。
3. 途中で「ペアリング鍵」を聞かれるので、1 でコピーした鍵を**そのまま**貼る（前後に空白や改行を入れない）→「ショートカットを追加」。
4. iPhone の **設定 → アプリ → ショートカット → 詳細 →「大量のデータの共有を許可」をオン**。
   （歩数は1日に数百件の記録があるため必要。PocketHeso に渡るのは日ごとの合計だけ）
5. PocketHeso に戻り、「運動を受け取る」を1回実行する。初回はヘルスケアの許可画面が出るので、
   **歩数** と **ウォーキング＋ランニングの距離** の読み取りを許可する。

### 1-2 毎回
1. PocketHeso の **「運動を受け取る」** をタップ → ショートカットが開いて自動で実行される。
2. 「PocketHeso に戻って貼り付けてください」と通知が出たら、PocketHeso に戻る（画面左上の戻る表示か、ホーム画面から）。
3. **「貼り付けて受け取る」** をタップ（貼り付けの許可を聞かれたら「ペースト」）。
   うまく貼れない時は、入力欄を長押し →「ペースト」で手で貼る。
4. 確認画面の「今回増える燃料・メダル」を見て **確定**。

- 受け取れるのは**今日と過去2日分**。3日以上あけると、それより前の日の歩数は受け取れない。
- 1日に何回受け取っても二重取りにはならない（その日の増えた分だけ加算される）。いつ受け取っても損はない。
- 自動実行（オートメーション）は使わない。iPhone がロックされて10分たつとヘルスケアが読めなくなるため。
- ショートカットが外部に送るものはない。コードはクリップボード経由で PocketHeso に渡るだけ。

### 1-3 受け取れない時
| 表示 | 原因 | 対処 |
|---|---|---|
| 受け取りコードが壊れています | コピーが途中で切れた・別の文字を貼った | ショートカットをもう一度実行して貼り直す |
| ペアリング鍵が一致しません | ショートカットに入れた鍵が PocketHeso の鍵と違う（1文字違い・空白混入・別の iPhone の鍵） | ショートカットを削除して 1-1 からやり直すか、ショートカットを編集して先頭の「テキスト」の鍵を貼り直す |
| 古いコードです | 30分以上前にコピーしたコードを貼った | ショートカットをもう一度実行してすぐ貼る |
| このコードの版には対応していません | ショートカットが古い／新しい | iCloud リンクから追加し直し、PocketHeso を再読み込みする |
| 「〜の歩数が範囲外のため捨てました」などの注意 | 1日10万歩・10万m を超える値や読めない日付があった | その項目だけ受け取られない。他の日はそのまま受け取れる |
| ショートカットで「共有しようとしていますが、それは許可されていません」 | 1-1 の 4 が未設定 | 設定 →「大量のデータの共有を許可」をオン |
| 歩数が 0 になる | ヘルスケアの読み取りが許可されていない | 設定 → ヘルスケア → データアクセスとデバイス → ショートカット → 歩数・距離をオン |

## 2. 作り方（作者向け: iCloud リンクを作る・作り直す）

試作確認用の画面: PocketHeso のプレビュー版で下部の「spike: shortcut」（本番以外に表示）。
「ショートカットを開く」→ 通知 → 戻る →「貼り付け(read)」で、「デコード」と「検証（parseShortcutCode）」欄に結果が出る。
検証欄の鍵は試験用 `abcdefghijklmnop`（下の 2-1 と同じ）が初期値。

### 2-0 先に知っておく操作
- **アクションの追加**: 画面下の検索欄「アクションを検索」にアクション名を入れ、出てきたものをタップ（一番下に追加される）。
  長押しでドラッグすると順番を変えられる。
- **青い文字**はタップして値を選ぶ設定項目。**灰色の文字**（例: 「テキスト」）はタップして入力する欄。
- **変数を入れる**: 入力欄をタップ → キーボードの上に出るバーの「変数を選択」（または候補のバブル）→ 入れたい変数をタップ。
  入れた変数はバブル（色付きの角丸）で表示される。
- **変数のプロパティ**（例: 日付の「年」、ヘルスケアサンプルの「値」）: 入れたバブルをタップ → 一覧から項目を選ぶ。
- **名前付き変数**: この手順では「変数を設定」アクションで名前を付け、後で名前で選ぶ。途中結果の取り違えを防ぐため。
- 表記は iOS 26 日本語版を想定。名前が少し違う場合は（ ）内の英語名に近いものを選び、どこが違ったかメモしておく。
- 各ブロックの最後に **「確認」** がある。そこで一度 ▶ で実行し、表示が合っていれば「結果を表示」アクションを削除して次へ進む。

### 2-1 鍵
| # | アクション | 設定 |
|---|---|---|
| 1 | テキスト（Text） | `abcdefghijklmnop`（試験用の仮の鍵。本番では PWA が表示する16文字に置き換える） |
| 2 | 変数を設定（Set Variable） | 変数名: `鍵`、入力: 1 の「テキスト」 |

鍵は PWA 側と1文字でも違うと sig が合わず、受け取りで弾かれる（エラーは PWA 側で出る）。前後に空白や改行を入れない。

### 2-2 日ごとの歩数・距離（今日・昨日・一昨日の3日分）
「繰り返す」の中は **3回** 実行される。1回目が今日、2回目が昨日、3回目が一昨日。

| # | アクション | 設定 |
|---|---|---|
| 3 | 繰り返す（Repeat） | 回数: `3`。以下 4〜22 は「繰り返す」と「繰り返しの終了」の**間**に入れる |
| 4 | 計算（Calculate） | 「繰り返しインデックス」 `−` `1`（1回目→0、2回目→1、3回目→2） |
| 5 | 日付を調整（Adjust Date） | 対象の日付: 「現在の日付」、操作: **減算**、値: 4 の「計算結果」、単位: **日**。⚠ 下の注意を参照 |
| 6 | 日付を調整 | 対象の日付: 5 の出力（**「現在の日付」という名前で表示される**。下の注意を参照）、操作: **日の始まりを取得**（Get Start of Day） |
| 7 | 変数を設定 | 変数名: `開始`、入力: 6 の「調整済みの日付」 → その日の 0:00 |
| 8 | 日付を調整 | 対象の日付: 変数 `開始`、操作: **追加**、値: `1`、単位: **日** |
| 9 | 変数を設定 | 変数名: `終了`、入力: 8 の「調整済みの日付」 → 翌日の 0:00 |
| 10 | 日付をフォーマット（Format Date） | 日付: 変数 `開始`、日付フォーマット: **カスタム**、フォーマット文字列: `yyyy-MM-dd` |
| 11 | 変数を設定 | 変数名: `日`、入力: 10 の「フォーマット済みの日付」（例: `2026-09-24`） |
| 12 | ヘルスケアサンプルを検索（Find Health Samples） | 種類: **歩数**。「フィルタを追加」→ **開始日** / 条件 **が次の範囲内**（is between）/ 変数 `開始` と 変数 `終了`。並べ替え・制限はそのまま（制限オフ） |
| 13 | 統計を計算（Calculate Statistics） | 操作: **合計**、入力: 12 の「ヘルスケアサンプル」 |
| 14 | 数値を書式設定（Format Number） | 入力: 13 の「統計」、小数点以下: **0桁**（iOS 26 では「数値を丸める」が検索に出ない） |
| 14b | テキストを置き換える | 対象: 14 の「フォーマット済みの数値」、検索: `[^0-9]`、置き換え: 空欄、「正規表現」**オン**（**必須**。1000 以上だと `10,350` のように桁区切りが入り JSON が壊れる） |
| 15 | 変数を設定 | 変数名: `歩数`、入力: 14b の「更新されたテキスト」 |
| 16 | ヘルスケアサンプルを検索 | 種類: **ウォーキング＋ランニングの距離**。フィルタは 12 と同じ（開始日 が `開始` と `終了` の範囲内）。「値 が次と等しい」など**他のフィルタ行が付いていたら ⊖ で削除**（空欄のフィルタがあると0件になる） |
| 17 | 統計を計算 | 操作: **合計**、入力: 16 の「ヘルスケアサンプル」 |
| 18 | 計算 | 17 の「統計」 `×` `1000`（ヘルスケアの距離単位が km の場合。m 表示なら 18 は不要で、19 の入力を 17 にする） |
| 19 | 数値を書式設定 | 入力: 18 の「計算結果」、小数点以下: **0桁** |
| 19b | テキストを置き換える | 対象: 19 の「フォーマット済みの数値」、検索: `[^0-9]`、置き換え: 空欄、「正規表現」**オン**（14b と同じ理由で必須） |
| 20 | 変数を設定 | 変数名: `距離`、入力: 19b の「更新されたテキスト」 |
| 21 | テキスト | 下の文字をそのまま打ち、`〔 〕` の部分は変数のバブルに置き換える（`〔 〕` 自体は打たない）: |
|   |   | `{"d":"〔日〕","steps":〔歩数〕,"distM":〔距離〕}` |
| 22 | 結果を表示（Show Result）※確認用 | 21 の「テキスト」。**確認後に削除** |
| 23 | 繰り返しの終了 | （3 を追加すると自動で入る） |
| 24 | テキストを結合（Combine Text） | 入力: 「繰り返しの結果」、区切り: **カスタム** `,`（半角カンマ1文字） |
| 25 | 変数を設定 | 変数名: `days` |

**注意（5・6）**: 「日付を調整」の出力は、入力と同じ「現在の日付」という名前で表示される。
- 5 の対象の日付は、「変数を選択」の一覧で**グローバルの「現在の日付」**（どのアクションの下にも付いていないもの）を選ぶ。
  5 自身の出力を選ぶと自己参照になり、`日`・`歩数`・`距離` がすべて空になる（エラーは出ない）。
- 6 の対象の日付は、5 の直下に出る出力バブル（名前は「現在の日付」）を選ぶ。

**値が空のときの切り分け**: 「結果を表示」は入力が空だと何も出さずに次へ進む。
テキストに `A=〔変数〕 B=〔変数〕…` のようにラベルを付けて表示すると、どこから空になるか一度で分かる。

**確認（2-2）**: ▶ で実行 → 22 の表示が3回出て、1回目が今日の日付・歩数、2回目が昨日…になっていること。
歩数をヘルスケアアプリの「歩数」の各日の値と見比べ、メモする（ずれていたら iPhone＋Apple Watch の重複の可能性）。
- 6 に「日の始まりを取得」が無い場合: 6 を削除し、7 の入力を「10 と同じ `yyyy-MM-dd` にフォーマットした文字」にする（ショートカットは日付だけの文字を 0:00 として扱う）。その場合は並びを 5 → 10 → 7 → 8 → 9 → 11 にする。
- 22 の表示で数値に `,` が残っていたら、15・20 の入力が 14b・19b の「更新されたテキスト」になっているか確認する（14b を後から足しても 15 の入力は自動で切り替わらない）。

### 2-3 コード化とコピー
ワークアウトは取得しない（iOS 26 の「ヘルスケアサンプルを検索」に種類「ワークアウト」が無く、読み出すアクションも無い: D-022）。
旧版の 26〜35（ワークアウト）は削除し、番号を詰めた。旧手順で「ヘルスケアサンプルを検索（ワークアウト）」「各項目を繰り返す」「繰り返し項目を書式設定」などを
作っていたら、その繰り返しごと削除してから下の 26 を足す。

| # | アクション | 設定 |
|---|---|---|
| 26 | 日付をフォーマット | 日付: **グローバルの「現在の日付」**（5 の出力ではない。下の注意）、ISO 8601、「ISO 8601時刻を含める」**オン** |
| 27 | 変数を設定 | 変数名: `gen` |
| 28 | テキスト | `{"v":1,"gen":"〔gen〕","tz":"+09:00","days":[〔days〕]}` |
| 29 | Base64 エンコード（Base64 Encode） | モード: **エンコード**、入力: 28 の「テキスト」、改行: **なし**（▼ を開いて変更。既定は 76 文字ごとに改行が入る） |
| 30 | 変数を設定 | 変数名: `b64` |
| 31 | テキスト | `〔鍵〕〔b64〕`（間に空白や改行を入れない） |
| 32 | ハッシュを生成（Generate Hash） | 入力: 31 の「テキスト」、種類: **SHA256** |
| 33 | テキストを置き換える（Replace Text） | 検索: `^(.{16}).*$`、置き換え: `$1`、対象: 32 の「ハッシュ」。「正規表現」**オン** |
| 34 | 変数を設定 | 変数名: `sig` |
| 35 | テキスト | `PH1.〔b64〕.〔sig〕` |
| 36 | クリップボードにコピー（Copy to Clipboard） | 入力: 35 の「テキスト」 |
| 37 | 通知を表示（Show Notification） | `PocketHeso に戻って貼り付けてください` |

**注意（26）**: 5 の出力も「現在の日付」という名前なので、それを選ぶと繰り返し最後の値（2日前の同時刻）が `gen` になり、
PWA の鮮度チェック（±30分）で弾かれる。「変数を選択」でどのアクションの下にも付いていない「現在の日付」を選ぶ。

**確認（2-3）**: PWA「spike: shortcut」→「ショートカットを開く」→ 通知 → 戻る →「貼り付け(read)」（失敗したらもう一度、それでもだめなら欄を長押し→ペースト）。
「検証（parseShortcutCode）」欄に `"k": "health"` と `days` 3件が出れば完成（`"k": "error"` なら `code` を 1-3 の表で確認）。初回はヘルスケアの許可画面が出るので、歩数・ウォーキング＋ランニングの距離を許可する。
- 「このアクションは 256 個のヘルスケア項目を共有しようとしていますが、それは許可されていません」と出た場合:
  **設定 → アプリ → ショートカット → 詳細 →「大量のデータの共有を許可」をオン**。歩数は1日に数百サンプルあるため出る（外部へ送られるのは合計値の JSON だけ）。

### 2-4 読み込み時の質問（鍵を利用者に入れてもらう）
iCloud リンクから追加する人が、自分のペアリング鍵を入れられるようにする。
1. ショートカットの編集画面で、上部の名前 →「詳細」（または ⓘ）→ **「読み込み時の質問を追加」**（Add Import Question… / Set Up）。
2. 対象に **1 の「テキスト」**（鍵）を選ぶ。質問文: `PocketHeso の設定に表示されている16文字のペアリング鍵を貼ってください`、既定値は空にする。
3. 1 の「テキスト」に入っている試験用の鍵は、共有時に質問の答えで置き換わる（既定値として共有されない）ことを確認する。

### 2-5 iCloud リンクを作る
1. ショートカットを長押し →「共有」→「iCloud リンクをコピー」（初回は「設定 → アプリ → ショートカット」で共有の許可を求められることがある）。
2. リンクをこのファイル冒頭の「iCloud 共有リンク」に記入する。
3. 確認: 自分の iPhone でリンクを開き、別名で追加 → 鍵の質問が出る → ヘルスケアの許可が改めて求められる → 受け取れる。
   確認後、別名で追加したものは削除する（PocketHeso が起動するのは `PocketHeso Sync` という名前のもの）。
4. ショートカットを直したら、リンクを作り直して差し替える（古いリンクは古い版のまま）。
